# Growth Language and Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace growth-only mathematical expressions with a safe Rust-like scalar language supporting immutable variables, `if/else`, booleans, CPU/CUDA parity, traces, and multidimensional plot sampling.

**Architecture:** A span-preserving lexer and parser produce an untyped AST; one type-check pass resolves all external kernel inputs, implicit `self`, parameters, local bindings, and whitelisted functions into stable symbol IDs. The same typed AST feeds CPU evaluation, trace/plot evaluation, interval diagnostics, and CUDA source generation, so no backend reinterprets source independently.

**Tech Stack:** Rust 2024, existing diagnostic and experiment-service types, NVRTC CUDA code generation, cargo test.

**Spec:** `docs/superpowers/specs/2026-08-21-interactive-experiment-workbench-design.md`

## Global Constraints

- Kernel input symbols are generated by routing and remain read-only.
- `self` is implicit and is not a kernel input.
- Local bindings are immutable; no assignment, loops, recursion, arrays, allocation, I/O, clock, or unseeded random source.
- `if/else`, `&&`, and `||` evaluate only the selected/required branch.
- GrowthRate and DirectUpdate semantics remain explicit serialized metadata.
- CPU and CUDA consume the same typed AST and must agree within `1e-5` on finite fixtures.
- An invalid or non-finite candidate step is discarded before buffer swap.
